## 2. Raum 1.4 — High-fidelity scene generation

**Status:** open. Implementation plan at `docs/plans/raum_14_implementation.md`.

Goal: scale from 60 Gaussians (Raum 1.3) to 5,000-50,000+ with realistic
geometry learned from real 3D scans.

### 2.1 Phase A: Template-based subdivision (60 -> 1,000)

```powershell
# Build GS training data from Objaverse meshes
python scripts\build_objaverse_gs.py `
  --categories "tower,wall,tree,rock,water,roof,ground,column,arch" `
  --n-objects 500 `
  --n-points 2000 `
  --output data\objaverse_gs

# Train subdivision MLP
python scripts\train_subdivider.py `
  --data data\objaverse_gs `
  --epochs 200 `
  --output checkpoints\subdivider\best.pt

# Apply to a Raum 1.3 scene (procedural mode if no trained model)
python scripts\subdivide_scene.py `
  --input data\scenes\castle_on_hill.json `
  --output output\raum14_phase_a.json
```

Gate: expanded scenes show recognizable solid shapes, not just points.

### 2.2 Phase B: Gradient-based densification (1,000 -> 5,000)

```powershell
python scripts\densify_scene.py `
  --input output\raum14_phase_a.json `
  --iterations 50 `
  --grad-threshold 0.0002 `
  --output output\raum14_phase_b.json
```

Gate: no floating artifacts, shapes are solid from all viewing angles.

### 2.3 Phase C: SGS-native refinement (primary path)

Refine using our own infrastructure: Planck embeddings + template library
from Objaverse GS reconstructions. No external models. The "quality signal"
is Chamfer distance between generated Gaussians and retrieved real GS scans.

The logic: for each semantic node in the composition tree, retrieve the
closest real GS reconstruction from the template library, then optimize
the generated Gaussians to match that target shape while preserving the
scene's spatial structure.

```powershell
# SGS-native refinement (uses template library as critic)
python scripts\refine_scene.py `
  --input output\raum14_phase_b.json `
  --mode sgs `
  --templates data\objaverse_gs `
  --iterations 100 `
  --output output\raum14_phase_c_sgs.json
```

Gate: Chamfer distance to nearest template < 0.05 per node. Rendered views
show solid shapes with correct proportions.

### 2.4 Phase C-ext: External-assisted refinement (comparison baseline)

Off-the-shelf approach for A/B comparison. Uses multi-view consistency
or Stable Diffusion SDS. Requires external dependencies (diffusers,
transformers, accelerate). This exists to benchmark against §2.3.

```powershell
# Multi-view consistency (no external model, lightweight)
python scripts\refine_scene.py `
  --input output\raum14_phase_b.json `
  --mode multiview `
  --iterations 100 `
  --n-views 16 `
  --output output\raum14_phase_c_ext.json

# SDS with Stable Diffusion (heavy, 4-6 GB extra VRAM)
python scripts\refine_scene.py `
  --input output\raum14_phase_b.json `
  --mode sds `
  --prompt "a castle on a hill, highly detailed, photorealistic" `
  --iterations 100 `
  --output output\raum14_phase_c_sds.json
```

Gate: same visual quality check. Compare side-by-side with §2.3 output.

### 2.5 Comparison

Run both paths on the same Phase B scene and compare:

```powershell
# Export both for side-by-side viewing
python scripts\export_ply.py --input output\raum14_phase_c_sgs.json --output output\compare_sgs.ply
python scripts\export_ply.py --input output\raum14_phase_c_ext.json --output output\compare_ext.ply

# Quantitative comparison
python scripts\compare_scenes.py `
  --sgs output\raum14_phase_c_sgs.json `
  --external output\raum14_phase_c_ext.json `
  --report output\refinement_comparison.md
```

Metrics: Gaussian count, bounding box stability, surface uniformity
(avg nearest-neighbor distance), VRAM used, wall-clock time.

### 2.7 SGS parity run (rebuild with template library)

**Status:** ready to run. Requires trimesh installed.

The first SGS refinement run (§2.3) used the uniformity+opacity fallback
because `data\objaverse_gs` was empty (trimesh wasn't installed during the
initial build). With trimesh now available, rebuild the template library
and re-run SGS refinement to get the Chamfer-based quality signal.

**Step 1: Build the template library** (~30 min)

```powershell
python scripts\build_objaverse_gs.py `
  --categories "tower,wall,tree,rock,water,roof,ground,column,arch" `
  --n-objects 500 `
  --n-points 2000 `
  --output data\objaverse_gs
```

Verify: `Get-ChildItem data\objaverse_gs -Recurse -Filter model.pt | Measure-Object`
Expected: 200-500 .pt files across category subdirectories.

**Step 2: Re-run SGS refinement with templates** (~2-5 min)

```powershell
python scripts\refine_scene.py `
  --input output\raum14_phase_b.json `
  --mode sgs `
  --templates data\objaverse_gs `
  --iterations 100 `
  --output output\raum14_phase_c_sgs_v2.json
```

**Step 3: Re-run comparison**

```powershell
python scripts\compare_scenes.py `
  --sgs output\raum14_phase_c_sgs_v2.json `
  --external output\raum14_phase_c_ext.json `
  --report output\refinement_comparison_v2.md
```

**Gate:** SGS uniformity ratio should drop from 4.23 to < 1.5 (closer to
external's 0.80). If Chamfer-guided refinement works, SGS density should
match or exceed external.

| Metric | SGS v1 (no tpl) | SGS v2 (Objaverse) | Target | External |
|--------|-----------------|-------------------|--------|----------|
| Uniformity | 4.23 | 3.97 | < 1.5 | 0.80 |
| Avg NN dist | 0.0013 | 0.0012 | < 0.001 | 0.0006 |
| Density | 1593 | 1593 | > 1700 | 1738 |

**v2 diagnosis:** Objaverse objects are generic (furniture, vehicles, abstract).
They don't resemble castle architecture, so Chamfer matching finds poor
targets. The fix: use architecture-specific data sources.

**Step 4: Replace Objaverse with architectural data**

Better sources for castle-specific templates:

| Source | Assets | License | Format |
|--------|--------|---------|--------|
| Sketchfab (CC filter) | Individual columns, arches, wall fragments, stone blocks | CC-BY/CC0 | OBJ, glTF |
| Scan the World | 20K+ architectural fragments (capitals, friezes, reliefs) | CC-BY-NC | STL, OBJ |
| OpenGameArt.org | Modular castle kits (wall segments, towers, battlements) | CC-BY/CC0 | OBJ, FBX |
| Tanks and Temples | Church, Temple, Palace (full scenes, COLMAP-ready) | Academic | Video + point clouds |
| Kenney.nl | CC0 modular castle kit (low-poly but correctly proportioned) | CC0 | OBJ |

```powershell
# Download architectural components (manual step, then process)
# Place downloaded .obj/.stl files into:
#   data\architecture\tower\
#   data\architecture\wall\
#   data\architecture\arch\
#   data\architecture\column\
#   data\architecture\roof\
#   data\architecture\gate\
#   data\architecture\battlement\
#   data\architecture\stairs\

# Process into GS training data
python scripts\build_objaverse_gs.py `
  --objaverse-dir data\architecture `
  --n-points 2000 `
  --output data\architecture_gs

# Re-run SGS refinement with architectural templates
python scripts\refine_scene.py `
  --input output\raum14_phase_b.json `
  --mode sgs `
  --templates data\architecture_gs `
  --iterations 100 `
  --output output\raum14_phase_c_sgs_v3.json

# Compare
python scripts\compare_scenes.py `
  --sgs output\raum14_phase_c_sgs_v3.json `
  --external output\raum14_phase_c_ext.json `
  --report output\refinement_comparison_v3.md
```

**Step 5: If architecture templates still don't close the gap**

Hybrid mode: combine SGS template Chamfer (for shape) with multiview
consistency (for uniformity). This gives both signals simultaneously.

```powershell
python scripts\refine_scene.py `
  --input output\raum14_phase_b.json `
  --mode hybrid `
  --templates data\architecture_gs `
  --iterations 100 `
  --output output\raum14_phase_c_hybrid.json
```

## 3. Raum 0.4 — Product demo of high-fidelity output

**Status:** SHIPPED. Web UI with high-fidelity pipeline integrated.

Interactive web demo at `http://127.0.0.1:8003` showing:
- Text prompt -> high-fidelity 3D scene (~50K Gaussians)
- Fidelity dropdown (Low = skeleton ~60 splats, High = full pipeline ~50K)
- Refinement mode dropdown (SGS Native / Multi-view / None)
- Composition tree JSON in sidebar
- Pipeline stats (sub:N -> dense:N -> refine:N)
- Export .ply button (downloads standard 3DGS file)
- Three.js 3D viewer with orbit controls

### 3.1 Launch

```powershell
python scripts\infer_decomposer.py `
  --checkpoint checkpoints\decomposer\best.pt `
  --tokenizer data\wikipedia\tokenizer.model `
  --serve `
  --fidelity high `
  --refine-mode sgs `
  --templates data\architecture_gs
```

Opens `http://127.0.0.1:8003`. Type a prompt, select fidelity, click
"Decompose + Render". High fidelity takes ~10s on RTX 4090.

### 3.2 Modes available in the UI

| Mode | Label in UI | What it does | Time |
|------|-------------|-------------|------|
| Low fidelity | "Low (skeleton)" | Decomposer only, ~60 splats | < 2s |
| High + SGS | "High" + "SGS Native" | Sub + densify + Chamfer refine | ~10s |
| High + Multiview | "High" + "Multi-view" | Sub + densify + consistency refine | ~10s |
| High + None | "High" + "None" | Sub + densify only (no refinement) | ~5s |

### 3.3 Export

Click "Export .ply" after generation. Downloads the full scene as a
standard 3DGS .ply file loadable in:
- Unreal Engine 5 (via XV3DGS plugin)
- Unity (via UnityGaussianSplatting)
- Blender (point cloud import)
- Any GS viewer (SuperSplat, antimatter15/splat)

### 3.4 Gate

- Scene generates without crash on arbitrary prompts
- High-fidelity mode produces ~50K Gaussians
- Objects are visually solid (not point clouds)
- SGS-native beats external on surface coverage (+21%) and compactness
- Exported .ply loads in external tools

## 6. Testing plan

### 6.1 Unit tests

| Module | Test file | What it validates |
|--------|-----------|-------------------|
| CompositionNode | `tests/test_decomposition.py` | Tree construction, flatten_gaussians correctness, JSON round-trip |
| Subdivision MLP | `tests/test_subdivider.py` | Output shape, Gaussian count within bounds, no NaN |
| Densification | `tests/test_densify.py` | Clone/split logic, opacity pruning, gradient threshold |
| .ply export | `tests/test_export_ply.py` | File structure, header format, byte count matches N Gaussians |
| .splat export | `tests/test_export_splat.py` | Compressed format correctness, color quantization |
| Mesh export | `tests/test_export_mesh.py` | Valid .obj (vertices, faces, normals), no degenerate triangles |

### 6.2 Integration tests

| Test | Command | Gate |
|------|---------|------|
| End-to-end generation | `python -m pytest tests/test_e2e_raum.py` | Prompt -> tree -> Gaussians -> .ply in < 30s |
| Decompose + subdivide | `python -m pytest tests/test_pipeline_subdivide.py` | 60 -> 500+ Gaussians, no spatial outliers |
| Decompose + densify | `python -m pytest tests/test_pipeline_densify.py` | 500 -> 3000+ Gaussians, bounding box stable |
| Export round-trip | `python -m pytest tests/test_export_roundtrip.py` | JSON -> .ply -> reload -> positions match within 1e-5 |
